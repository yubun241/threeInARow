# 3 In A Row

藤井工藝 / Ver.1.0

3手制限の三目並べです。各プレイヤーの印は盤上に最大3つまでしか存在できず、4つ目を置くと一番古い印が自動的に消えます。GitHub Pages 等の静的ホスティングにそのまま置ける単一の `index.html` で動作し、外部依存（CDN・サーバー・ビルドツール）は一切ありません。

## ルール

- ◯が先攻、交互に1手ずつ盤面に置く。
- 自分の印が4つ目になった瞬間、最も古い自分の印が1つ消える（対戦相手の印には影響しない）。
- 縦・横・斜めのいずれかに3つ揃った時点でその印の勝利。
- 同一局面（印の配置・キューの順序・手番）が一度出現した盤面に戻った場合、または80手に達した場合は引き分け（盤面ループ）として終了する。

## 画面構成

1. **タイトル画面** — 「3 In A Row / 藤井工藝 / Ver.1.0」を表示し、「タップして開始」でセットアップ画面へ。
2. **セットアップ画面** — モードを選択して開始する。
3. **ゲーム画面** — 対人・対CPUの対局を行う。
4. **ML学習結果画面** — 学習の進行状況とベンチマーク結果を表示する。

## モード

### 対人

2人で同じ画面を操作して対局する。

### 対CPU

- 先攻（◯）/ 後攻（✖）/ ランダム から自分の手番を選べる。
- CPUの強さは3段階。
  - **ランダム** — 空いているセルにランダムに着手する。
  - **ミニマックス（強）** — 深さ限定・アルファベータ枝刈り付きの先読み探索（深さ7、最大180msの時間制限）。完全解析ではないが、ヒューリスティック評価（2連続の検出・中央セルの重み付け）と合わせて高い精度で先読みする。
  - **Q学習（学習型）** — 下記「ML学習」で蓄積したQテーブルを使って着手する。学習済みの局面が無い場合はランダムに着手する（学習量に応じてのみ強くなる仕様）。

### ML学習

- 表形式Q学習（tabular Q-learning）による自己対戦（self-play）でCPUを強化する。
- 学習エピソード数（100〜50,000、既定5,000）を指定して「学習を実行」を押すと、◯×が同じQテーブルを共有して自己対戦を繰り返し、テーブルを更新する。
- 学習後、自動的にランダムCPU・ミニマックスCPUと対戦するベンチマークを実行し、学習効果を勝敗数で確認できる。
- 学習データ（Qテーブル）はブラウザの localStorage に保存され、次回起動時にも引き継がれる。「学習データをリセット」でいつでも初期化できる。

## ログ・CSVの扱い

- 対局ログ（player, hand, timestamp, x, y）は対局終了時に **自動的にはダウンロードされない**。ブラウザの localStorage に静かに積み重ねられるだけ。
- ファイルが欲しいときは明示的に以下のボタンを押す。
  - **Save & Reset** — 現在進行中の対局ログをCSVとして書き出し、即座にリセットする。
  - **Export History** — これまでに保存された全対局を1つのCSV（先頭列に game_no）として書き出す。

## 技術的なポイント

- **状態表現**: 盤面は「印の配置」だけでなく「各プレイヤーの印が置かれた順序（FIFOキュー、最大3件）」を保持する。これは4つ目を置いたときにどの印が消えるかを決定するために必要。
- **Q学習の状態キー**: 「手番側から見た相対表現」（自分のキュー / 相手のキュー）でエンコードしている。◯と✖で1つのQテーブルを共有でき、自己対戦の経験を両者で再利用できるため学習効率が高い。
- **Q学習の更新則**: ゼロサム交互ゲーム向けのnegamax式ブートストラップ（`target = γ × (-相手番の最大Q値)`、勝利時は+1、引き分け時は0）。
- **盤面の対称性（回転・反転）による状態圧縮は未実装**。学習速度をさらに上げたい場合の拡張候補として残している。
- 開発時にエンジン部分（盤面ロジック・ミニマックス・Q学習）だけを切り出し、Node.js上で214件のユニットテストを実行して検証済み（FIFO削除の正確性、勝敗判定、ミニマックスの必勝手発見/ブロック、ミニマックス対ランダム60戦60勝、Q学習の自己対戦による勝率改善など）。

## 既知の制限

- ミニマックスは深さ限定探索であり、厳密な完全解析（あらゆる繰り返し局面を含めた理論的最善手）ではない。
- Q学習は学習量に強さが完全に依存するため、初回利用時はまずML学習モードで一度学習させることを推奨する。
